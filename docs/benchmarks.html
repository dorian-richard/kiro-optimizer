kopt benchmarks

What kopt changes in what an agent reads, measured three ways: an offline benchmark of one exploration step on 138 tasks in 11 languages against CodeGraph, KiroGraph and native Kiro tools; real agents solving 21 tasks with and without kopt; and kopt's command-output filters. A last section covers indexing on two large repositories. Every number on this page comes from a result file committed in bench/results, and none of them is a Kiro credit: Kiro credits have not been measured by us (see Limits). Teams can measure their own with kopt bench ab.

kopt 0.2.0 (git tag v0.2.0), the release that follows the v0.1 prototype. Measured on 2026-10-09 and 2026-10-10. Builds and dates per data set: Data sources and versions. An HTML version with charts, generated from the same data, is docs/benchmarks.html, published at https://dorian-richard.github.io/kiro-optimizer/benchmarks.html.

At a glance #

  • Offline, one exploration step, 138 tasks. One kopt_find call in pack mode finds every expected file and symbol in 108/138 (78%) of the tasks, at a median of 1,299 tokens. CodeGraph finds 79/138 (57%) at 8,315, a disciplined native Kiro agent (grep, then line ranges) 54/138 (39%) at 6,675, and KiroGraph 4/138 (3%). These tasks guided the v0.2 work; on 22 held-out tasks written before any measurement, kopt finds 19/22 (86%) and native ranged reads 5/22 (23%).
  • Real agents, code exploration. Over 15 tasks on 9 open-source repositories, the measured session cost (re-based to a 12k-token prefix) is -23% [-38%, -8%] with kopt, lower in 13/15 tasks (sign test p = 0.007), with every answer correct in both arms. Over every v0.2 run pooled: -18% [-31%, -5%].
  • Real agents, test diagnosis. No measurable saving: +16% [-31%, +67%] over 6 tasks. kopt cuts what the agent reads, not the number of calls.
  • Command output. On 50 committed test, build and git outputs (45 generated in each tool's format, 5 real runs), kopt's filters return 10,402 of 286,154 tokens (96.4% removed). In the agent runs, kopt run turned 152.2k tokens of raw test output into 15.2k.
  • Large repositories. On elasticsearch (33,090 files indexed), search answers 32 s after the first start and callers 87 s; the index takes 941 MB and the first build peaks at 2.04 GB of memory.
  • Not measured: Kiro credits. The offline benchmark is a proxy, and the agent A/B runs outside Kiro. How Kiro turns tokens into credits is not published; the cost model kopt is built on is a hypothesis until an online A/B confirms it.

Offline retrieval: one exploration step on 11 languages #

kopt bench all gives every strategy the same input (the search phrase an agent would derive from the question) and measures one exploration step: the tokens returned to the model, and whether the verified gold files and symbols appear in them. A task counts as found when every gold file path and every gold symbol name is in the output. The corpus is 11 open-source repositories pinned at a tag, one per language, 12 to 15 tasks each (locate, explain, usage, impact), every gold item checked by reading the code and re-checked mechanically (kopt bench --verify). CodeGraph and KiroGraph ran in network-less containers on the same tasks, their default mode, one call of their main context tool each; their outputs are scored with the same metrics.

What the filters do not do well yet: there is no filter for node --test (TAP) output, whose failing test name and values the generic filter can drop; a passing Maven or Gradle run is reduced to its verdict, so a goal whose output is the content (mvn dependency:tree) needs a second call to read the log. The assertions of test/compress.filters.test.ts check, fixture by fixture, that the failing test, the assertion and the in-repo frames survive; they run on these fixtures, not on a corpus of real logs.

Real agents: A/B with logged tool calls #

The offline step says nothing about a whole session: how many turns the agent takes, whether it uses kopt at all, what it re-reads. This A/B runs real agents on real tasks, twice per arm and task, interleaved, with the same model, and logs every command they run through a wrapper.

  • Arm A (stock): read-only shell tools capped like Kiro's built-ins (search 100 matches / 10k characters, reads 2,000 lines, command output 2,000 lines / 100k characters).
  • Arm B (kopt): the same tools plus the kopt CLI (the same text as the MCP tools), kopt's steering and tool descriptions in the prompt, and kopt's real session governor (kopt hook).
  • Tasks: 15 exploration tasks (explain, usage, impact, locate) on 9 repositories of the offline corpus, and 6 test-diagnosis tasks: one realistic bug injected into a copy of this repository, find the root cause from the failing suite.
  • Run: 84 agents, 2 interleaved runs per arm and task, kopt build 983e221. Each task's value is the mean of its runs; confidence intervals are paired bootstrap 95% intervals over tasks (10,000 resamples), with an exact sign test.
  • Primary cost metric: the input context the agents' model really processed, summed over its requests, with the agent harness's own 34k-token prefix replaced by 12,000 tokens on every request (a Kiro-sized prefix); arm B keeps its extra prompt. It is the closest proxy here to what Kiro bills, and it is not a credit.

Full report: bench/results/agent-ab-final.md (and .json); method: bench/README.md.

Checks #

  • All 84 transcripts were audited: all 667 tool calls went through the wrapper, none for the wrong task or repetition, and the wrapper logs match the transcripts call for call.
  • Every answer is correct in both arms under both graders (lenient substring and strict whole-word): 30/30 exploration runs and 12/12 test runs, with 100% symbol recall.
  • All 106 kopt calls succeeded: find, read and refs exited 0, and kopt run returned the test command's own status (14 failing suites, 2 passing runs). No refused call, no governor block, no error text.
  • Flagged: one kopt run hit the agent harness's 120 s Bash timeout, and 6 of 21 kopt refs answers said "incomplete".

Two confounds, the same for both arms, explain most of the spread:

  • Flaky tests under load. 24 agents ran this repository's 813-test suite at the same time, and its timing-dependent tests failed in 9 of the 24 runs. Arm B spent 16 calls on these extra failures, arm A 4: kopt run names every failing test, while arm A's output was cut (next point).

Remaining blockers #

From the final run's logs and transcripts, in order of expected value:

  1. kopt use halved with the shorter prompt. kopt calls per exploration run 4.6 → 2.2, kopt share of tokens read 68% → 34%, 3/30 runs without kopt, 4.5 whole-file cat reads per 15 tasks (0 in r2), after the prompt lost its "no grep or whole-file reads" line. Proposed fix: restore one routing line (read code with kopt read #id|path:a-b, not cat/sed), then A/B the line within arm B.
  2. Timing-dependent tests in kopt's own suite fail under load. 9/24 test-task runs showed extra timing failures (kopt_run header duration, hooks fingerprint timeout, CLI ledger timeout); arm B chased them in 5/12 runs (16 calls, 14.5k tokens), arm A in 4/12 (4 calls). Proposed fix: make those tests independent of wall time; lower test-task concurrency; group kopt_run failures that share one assertion diff.
  3. A repeated kopt run after a timeout answers only "same as run X". B-rt5-r1: after an undelivered (timed-out) run, the re-run answered "same as run oe3b8f0 (call 1), no file changed since" with counts only; the agent paged the log in 4 reads (5.9k tokens). Proposed fix: a failing re-run repeats its compact failure list (<1k tokens).
  4. kopt refs misses calls on TypeScript and Rust receivers. kopt refs LocalWorkflow.cancel: 0 usages, 36 unresolved cancel (flow = new LocalWorkflow(...)); Rust self.create_next_batch_unprioritized only "possible"; md-usage B ran 7 and 5 native calls (3.8k, 2.5k tokens). Proposed fix: type TS/JS locals from new X(...) and typed parameters; resolve Rust self. to the impl type.
  5. The completeness check counts mentions in comments. kopt refs autobatch: "incomplete: 19 functions name autobatch with no reference linked" from test comments ("we can autobatch"). Proposed fix: skip comments and string literals in the completeness text check.
  6. Agents read callers with sed after a complete kopt refs answer. sf-usage-fail-early run 2: a complete 237-token refs answer, then 8.6k tokens of sed ranges to read the two callers (each listed with its #id). Proposed fix: steering: read a caller with kopt read #id; or inline bodies of up to 3 callers within budget.
  7. Measurement. arm A +25% between runs (same prompt, model and harness version); the harness caps failing output at ~10k characters (A delivered 90.0k of 192.6k logged tokens on test tasks). Proposed fix: keep arms interleaved in one window; report logged and delivered tokens; add exploration tasks.

The first one matters most: kopt use halved after the shorter prompt dropped the "No grep or whole-file reads" line (4.6 kopt calls per exploration run in round 2, 2.2 now). The saving held anyway, and whether restoring the line adds to it is untested.

What this A/B does not measure #

  • Kiro. The agents are Claude Code 2.1.295 sub-agents driving a shell wrapper, on one model (Claude Opus 5.5). Arm B reads kopt's tool descriptions in the prompt in CLI spelling, where Kiro sends MCP schemas; Kiro's own system prompt and tool schemas are modeled by the 12k-token prefix.
  • Credits. The primary metric is measured context, not what Kiro bills.
  • Edits and long sessions. Every task is read-only, from 2 to 18 tool calls per task on average; no multi-task spec, no autopilot run, no compaction.
  • Parts of kopt. The governor never blocked (0 blocks), prompt pointers are off by default, and the kopt-explorer sub-agent and the output steering were not exercised.
  • Other stacks. Exploration tasks come from the offline corpus (not held out); the test tasks are on this TypeScript repository only.

Method and fairness #

  • Measured baselines only. Native strategies run real git grep and real file reads on the checkout; nothing is an assumed counterfactual. The native emulation favours the native side: its grep picks the most selective keywords, shows the files with the most distinct keywords first, and reads return raw text with no line numbers.
  • Same input, same metrics. Every strategy gets the same search phrase; tokens are characters / 3 for all (no local Claude tokenizer: absolute values can be off by 25-45%, ratios are more robust).
  • Failures count. Tokens per found task include the tokens of the tasks a strategy missed; the A/B is reported on every task (both arms solved all of them).
  • Pre-registered tasks. Corpus tasks were committed before kopt was measured on them, held-out tasks before any measurement at all; neither is changed after a result.
  • Competitors in their default mode. One call of their main context tool, default arguments, a fresh MCP session per task (their best first-call behaviour), in containers with no network. Their index times were measured in a Linux VM under other load and are not compared with kopt's.
  • "Found" is generous to outputs that list names. A name in a relationship map counts even when its code is not shown. Definition recall is the stricter measure: the "Mean definition recall" column of the headline table, and the def recall column of each bench/results/<repo>.md.
  • Real agents, interleaved. Both arms ran in the same window, in a seeded interleaved order, with the same model and harness; the comparison is within a run, paired by task.
  • Raw data. Every competitor output, every agent's commands (with the tokens of each) and final answer (bench/results/agent-ab-final.json; the wrapper's own per-call logs of rounds 1, 2 and the final run in bench/agentab/logs/), and the per-task results are committed; kopt's own outputs are regenerable (kopt bench --raw).

The full protocol is in bench/README.md and bench/competitors/README.md.

Limits: what these numbers are not #

  • The offline proxy is not credits. It sees one step. It does not see the number of turns, the model's output, the context re-billed on every turn, compaction, the fixed prompt, or an agent that ignores kopt. A proxy can point the opposite way from reality (another code-graph tool's offline savings turned into losses in its own live runs).
  • Kiro credits were not measured by us. The online harness kopt bench ab passed its preflight against the real kiro-cli 2.28, but its one headless request was refused: Kiro's anti-abuse checks had suspended the account (a Free account; 0 credits spent). We stopped there and have run no automated Kiro session since.
  • The cost model is a hypothesis. kopt is built on the assumption that Kiro bills each request according to its total size, so a token that enters the context is paid again on every later request. Kiro documents that it bills per request, not how request size, output or prompt caching weigh in. If cached context is discounted, the saving on re-billed context shrinks, and the saving on turns and on new tokens remains.
  • The agent A/B is not Kiro. See What this A/B does not measure.
  • Measure on your own repository. kopt bench ab runs your own questions through the real Kiro CLI, with and without kopt, and compares the credits Kiro bills on the tasks both arms answered correctly. Log in yourself first: automated sessions can trigger Kiro's anti-abuse checks. Guide: bench/ab/README.md; a step-by-step test plan in French: TESTING.md.
kopt bench ab --check --repo ~/src/my-repo --tasks my-tasks.json                    # preflight, no prompt sent
kopt bench ab --repo ~/src/my-repo --tasks my-tasks.json --max-credits 60 --reps 2  # the campaign
kopt bench ab report --out ~/src/my-repo-kopt-ab                                    # rebuild the report

The decision rule is fixed before the runs: kopt is worth rolling out when, on the pairs both arms answered correctly, it saves at least 20% of the credits with a 95% CI that excludes 0 and is cheaper on more pairs than not; when the evidence is large enough (at least 5 tasks and 10 pairs, or a sign test below 0.05 over at least 3 tasks); when its correctness is not lower than stock Kiro's by more than one run (timeouts, missing answers, crashes and errors count as wrong answers); and when it does not fail more often than stock Kiro.

Reproduce #

From a clone, with Node 22.13 or later. The checkouts are read-only and gitignored; their code is never executed.

npm ci && npm run build
node dist/bin.js bench all --clone                     # 11 repositories: verify, index, quality, strategies
node dist/bin.js bench all --index-dir /tmp/kopt-idx   # the same, with the indexes outside the checkouts
node bench/compress/run.mjs                            # compression table -> bench/results/compression.{md,json}
node bench/scale/run.mjs --repo <large checkout> --out /tmp/scale.md
npm run bench:page                                     # rebuild docs/BENCHMARKS.md, docs/benchmarks.html and the marked numbers of README.md and docs/ARCHITECTURE.md
npm run bench:page -- --check                          # fail when a generated file is out of date

The competitor runs need Docker (bench/competitors/run.sh, see its README); the agent A/B needs an agent runner (bench/agentab, see bench/README.md).
